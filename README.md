# Logistics Network — Mindustry Java Mod

Factorio 风格的物流网络系统（Logistics Network）。完全用 Java 实现，无脚本依赖。

## 内容（4 个建筑 + 1 个单位）

| 建筑 | 对应 Factorio | 作用 |
|---|---|---|
| **物流基站** (logistics-base, 3x3) | 机器人指挥塔 | 贴图采用**原版单位物流装载点（Unit Cargo Loader）**。生产机制与原版 **UnitFactory 一致**（进度条、电力效率影响建造速度、断电冻结进度、完成时有建造动画和音效），但**不需要物品**，只耗电 **1200/s**。每 **60 秒**生产一架（首个同样 60 秒），默认最多 1 架（可改 `maxBots`）。**无人机与生产它的基站绑定**：拆基站无人机全部消失；**基站供电水平直接影响对应无人机的移动速度**（满电全速、低电慢速、断电停飞）。**建造特效只在有电且未达上限时显示**；**无最低电力门槛**（只要有电就生产，速度按比例）；电力条为原版默认颜色。 |
| **供应点** (logistics-supply-point, 2x2) | 红箱 Passive Provider Chest | 被动供应：无人机从这里取货。传送带/玩家可以直接放入物品。容量 480。 |
| **请求点** (logistics-request-point, 2x2) | 蓝箱 Requester Chest | 贴图采用**原版单位物流卸载点（Unit Cargo Unload Point）**，并**像原版一样用所选物品的颜色显示在方块上**（选中铜→蓝色标志，选中铅→紫色标志……）。点击方块打开物品选择界面，选中的物品会被无人机持续运来直到装满（容量 480）。也允许传送带直接送入该物品。**会自动向周围输出物品**（主动推送给相邻传送带/建筑，传送带也可抽取），适合给生产线供料。 |
| **储存点** (logistics-storage-point, 2x2) | 黄箱 Storage Chest | 储存：无人机把多余的物品存进来；有请求时也会从这里取货。容量 720。 |
| **物流无人机** (logistics-bot) | 物流机器人 | 飞行单位，速度快、无武器、血薄，可携带 40 个物品。由基站生成，不可被玩家操控/逻辑控制，不会被敌人优先锁定（但仍会被范围伤害打死）。 |

## 物流规则（无人机 AI）

- **空载时**：只在网络通电时接单，且**只为请求点（蓝箱）的需求取货**——取货量严格按蓝箱缺口裁剪，不会多拿。
- **需求阈值（防横跳）**：蓝箱缺口 ≥ `requestThreshold`（默认 **40**）才视为有需求。否则蓝箱被持续消耗时，无人机会为每 1 个缺失品往返一趟（蓝箱↔黄箱反复横跳）。有阈值后：蓝箱在 440~480 之间波动，每消耗满 40 个才批量补一趟（正好一架无人机的满载量）。
- **按缺口动态派单**：每个蓝箱允许的无人机数 = `缺口 ÷ 无人机载货量`（缺口 40 → 1 架，缺口 80 → 2 架，缺口 120 → 3 架，以此类推）。无人机接单前会"认领"目标蓝箱，认领满额后其他无人机自动去找别的蓝箱或待机；任务完成/放弃/无人机死亡时认领自动释放。
- **按库存动态取货（红箱/黄箱同机制）**：每个货源允许同时取货的无人机数 = `库存 ÷ 载货量`（红箱存 40 → 1 架，80 → 2 架，120 → 3 架）。认领货源时按此配额限制，防止多架无人机挤兑同一个货源；货物到手后立即释放货源坑位。
- **任务稳定性（防横跳）**：无人机选定任务后，飞往货源途中**不会**重新选任务（蓝箱缺口在阈值附近波动时，否则无人机会在多个红箱之间空跑横跳）；空载时优先继续服务自己认领的蓝箱（缺口大时连续多趟补货），直到它不再需要才换任务。
- **无人机不会主动把供应点（红箱）里的物品搬进储存点（黄箱）**；没有蓝箱需求时无人机保持空闲。
- **优先消耗黄箱库存**：取货时先拿储存点（黄箱）里的物品，黄箱没货才去供应点（红箱）取。
- **载货时**：优先送到最近的、需要该物品的请求点；**当蓝箱已满、身上货物无处可放时，才把物品放进储存点（黄箱）**；实在没地方放就丢弃货物（`clearItem`）。
- 黄箱同时可作为货源（蓝箱需求可从黄箱取货）；多人游戏中所有操作走 `Call.takeItems` / `Call.transferItemTo`（服务器权威）。

## 安装

1. 把 `build/libs/LogisticsNetworkDesktop.jar` 复制到 Mindustry 的 `mods/` 目录（或直接把整个项目文件夹放进去）。
2. 启动游戏 → 模组 → 启用 Logistics Network。
3. 四个建筑都在沙盒/战役中直接可用（`alwaysUnlocked = true`），无需研究。

## 构建

```bash
# 需要 JDK 17；依赖从 workspace/local-repo 本地镜像解析（v159.7 dependencies.jar）
gradle jar
# 产物: build/libs/LogisticsNetworkDesktop.jar
```

源码基于 Mindustry **v159.7**（v8 Build 159.7）API 编写并编译验证。

## 配置项（Java 源码内可调）

- `LogisticsBase.maxBots` — 每座基站最多无人机数（默认 **1**）
- `LogisticsBase.produceTime` — 生产一架所需 tick（默认 3600 = **60 秒**）
- `LogisticsAI.retargetTime` / `moveRange` / `transferRange` — AI 寻路参数
- `LogisticsAI.requestThreshold` — 蓝箱需求阈值（默认 40，缺口≥该值才补货）
- `LogisticsUnitTypes.logisticsBot` — 速度、血量、载货量等

## 贴图

`assets/sprites/` 下为程序生成的占位贴图（`gen-sprites.ps1` 可重新生成），可自行替换为美术资源。
